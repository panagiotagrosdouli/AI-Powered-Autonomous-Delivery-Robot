# AI-Powered Autonomous Delivery Robot with Predictive Pedestrian-Aware Navigation

## 1. Abstract

We implement a ROS 2 Jazzy research system combining a custom Gazebo Harmonic
robot, SLAM Toolbox, AMCL, Nav2 and forecast-aware command gating. Executed tests
establish simulated sensor publication, live map generation and two static-world
navigation goals. Three neural architectures were trained on explicitly synthetic
software fixtures. Real trajectory archives were inspected, but dataset terms
and sampling conventions remain unverified. The hypothesis that learned pedestrian
forecasts improve navigation is not yet experimentally evaluated.

## 2. Introduction

Moving people make static obstacle planning insufficient. This project investigates
whether explicit future pedestrian positions help a delivery robot compared with
Nav2's reactive costmaps. Reliable evidence requires a functioning navigation stack,
metric perception, valid data separation and matched repeatable experiments.

## 3. Related Work

SLAM Toolbox [1] provides online LiDAR pose-graph mapping. Social GAN [2] studies
socially conditioned multimodal trajectory forecasting and distributes processed
ETH/UCY data. The models implemented here do not reproduce Social GAN or its
social pooling; they are deterministic single-track CV/GRU/LSTM/Transformer
baselines. The literature review is limited and no novelty claim is made.

## 4. System Architecture

The robot has two driven wheels, passive casters, collision/inertial geometry,
LiDAR and RGB-D sensors. Gazebo publishes sensor and odometry data through ros_gz
bridges. robot_state_publisher supplies link transforms. Mapping and localization
are separate runs: SLAM first creates a map, AMCL then uses the saved output.
Navfn plans global paths and DWB controls locally, with obstacle/inflation costmaps,
behavior-tree goal execution, recoveries, waypoint following and velocity smoothing.
Condition-specific command routing is specified in INTEGRATION.md.

## 5. Methodology

Mapping consumes live simulated LiDAR and odometry. Evidence checks map changes
while moving and map-to-odom TF, preserving scans and the produced occupancy grid.
AMCL initializes near the simulator origin, maintains map-to-odom and feeds Nav2.
This validates operation, not geometric accuracy or global localization recovery.

For calibrated aligned RGB-D, an optical-frame point is
`X=(u-cx)Z/fx, Y=(v-cy)Z/fy, Z=depth_m`. Extrinsic conversion applies a unit-quaternion
rotation followed by translation. The offline YOLO utility rejects missing depth
and records source image hashes. Live synchronization and camera-to-ROS tracking
are not implemented, so camera performance is not claimed.

The baseline uses the most recent two observations: `p(t+k*dt)=p(t)+k*(p(t)-p(t-dt))`.
Recurrent models consume relative displacements using one 32-unit GRU or LSTM.
The Transformer uses a 32-dimensional embedding, sinusoidal temporal positions,
two four-head encoder layers and feed-forward width 64. Each architecture has a
linear head producing future displacement increments; cumulative increments are
anchored to the last observed position. The training objective is mean squared
position error, averaged over batch, horizon and two coordinate dimensions.

`ADE = mean_i mean_k ||prediction_ik - truth_ik||_2` and
`FDE = mean_i ||prediction_i,last - truth_i,last||_2`, in metres. Checkpoint selection
uses validation MSE only; held-out test windows are used after selection. Data
manifests enforce recording-level separation and file hashes, but correct scene
identities and source permissions still require verification by the experimenter.

The online gate compares robot unicycle forecasts with sampled pedestrian points
and slows/stops based on all-around LiDAR clearance. Invalid frames, numerical
values, stale source timestamps and command timeouts fail closed. Uncertainty,
continuous-time collision guarantees and physical braking dynamics are unsupported.

## 6. Experimental Setup

The executor ran Debian 13 with an official Ubuntu/Jazzy Docker image and official
Jazzy apt packages. Logs contain image digests and package versions. Gazebo used
headless software rendering. Navigation used a new map generated by the custom
robot in the indoor synthetic world, followed by a restarted simulator and AMCL.
The executed goal was (1,0) in map with a zero-yaw target. No moving pedestrians
were present in this navigation smoke trial.

Neural software tests used six generated tracks per split, 30 samples per track,
8 observed and 12 future samples at 0.4 s intervals, and five epochs of Adam at
0.001 with seed 42 and one CPU thread. Whole generated scenes were split before
window construction. These generated coordinates are not real pedestrian data.
Batch-one inference latency uses warm-up and perf_counter on this shared executor;
resource contention and lack of deployment-hardware equivalence limit interpretation.

## 7. Results

All numerical results are sourced from saved executed files. Simulation-probe.json
records actual sensor message counts and odometry displacement. mapping/probe.json
records new occupancy information over time. navigation/trial_A.json records the
latest goal outcome and elapsed simulation time. SYNTHETIC_RESULTS.md reports
actual synthetic-model ADE/FDE and CPU latency, with checkpoints and per-window
arrays retained. Programmatic figures show the generated map, the odometry path
and synthetic training histories. These are different coordinate/data domains.

**Pedestrian navigation comparison: NOT EXECUTED — NO EXPERIMENTAL RESULT AVAILABLE.**
No collision rate, real-data ADE/FDE, localization error, map accuracy, detection
accuracy/FPS, navigation success-rate estimate or scientific confidence interval
is available. A single successful goal is not a population-level success rate.

## 8. Discussion

The executed components provide an integration foundation. On the short synthetic
fixture, all neural models performed worse than CV; this is a software-test outcome,
not a negative result on real pedestrian navigation. A full study must isolate
gating from forecasting, preserve failed trials and avoid treating correlated
trajectory windows as independent experimental runs.

## 9. Limitations

No verified real-data training, live metric pedestrian detector/tracker, calibrated
prediction uncertainty, executed recorded-trajectory Gazebo replay, or matched
dynamic A/B/C/D trials exist. AMCL recovery and localization accuracy are untested.
The outdoor world, optional YOLO entry point and D-mode Nav2 integration are not
runtime verified. KDL warns about root-link inertia (kinematics still published);
Gazebo warns about its gz_frame_id extension, while measured sensor frames were
correct. Commands and tests are experimental and lack safety certification.
Disk constraints required removal of the training environment after checkpoints
and verification; use pinned requirements to recreate it on a larger host.

## 10. Conclusion

Custom simulated sensing, new map generation, AMCL and static Nav2 goal execution
were demonstrated. The research hypothesis remains unanswered. Completing real
metric perception, verified real-data training and controlled dynamic trials is
necessary before claiming pedestrian-aware navigation benefit.
